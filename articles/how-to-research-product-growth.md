# 调研一个产品的增长，到底该看什么

网上讲"某产品是怎么增长起来的"的文章很多，但绝大多数是复述：把官方博客、创始人访谈、几篇 VC 文章揉在一起，再贴一个流行标签，比如"PLG 教科书案例"。这种文章读起来很爽，拿去指导自己的产品却几乎必然踩坑，因为它回答的是"他们说自己是怎么增长的"，而不是"他们到底是怎么增长的"。

我把自己做产品深度调研的方法沉淀成了一套固定流程，也写成了可以让 AI 跑的 skill。这篇文章只讲其中最核心的一块：增长怎么调研。先说结论：增长调研是诊断，不是复述。你的任务是从可观察的证据里倒推出真实的增长引擎组合，判断每个引擎的成熟度，再区分哪些能复制、哪些不能。

## 一、先分类，再动手

在查任何资料之前，先用三个维度给产品定位：

| 维度 | 选项 | 为什么影响调研 |
|---|---|---|
| 资金与出身 | 独立开发 / 自筹 / VC / 大厂内部 / 上市 | 决定去哪找一手信源，决定风险的类型 |
| 增长引擎 | 下文详述的组合打分 | 决定增长模块的侧重点 |
| 可扩展性 | 插件 / API / SDK / MCP / 市场 / 无 | 决定生态是不是增长的一部分 |

分类不是走形式。独立开发者的产品，最好的信源是创始人的个人博客和透明化收入帖；上市公司，最好的信源是财报和年报；大厂内部产品，你几乎找不到"创始人故事"，重点要看母公司怎么给它分发流量。分类错了，后面所有检索方向都会错。

## 二、增长不是一个标签，是一组引擎的组合

这是整套方法里最重要的判断：几乎没有产品只靠一种方式增长。常见的引擎有九种：自助式 PLG、付费获客、KOL 达人、内容与 SEO、销售驱动、平台捆绑分发、网络效应、社区与口碑、渠道合作。

调研时给每个引擎打 0 到 3 分，每一分都要写出证据：

| 分数 | 含义 | 证据特征 |
|---|---|---|
| 3 | 主引擎，前两位的增长来源 | 增长能明确归因到它 |
| 2 | 显著贡献 | 有支撑证据，有可观的量 |
| 1 | 存在但不起作用 | 有动作没效果，或者只是愿景 |
| 0 | 不存在 | 没找到任何证据 |

关键是证据从哪来。不要看官网怎么说，要看产品实际在做什么：应用商店里有没有投广告、LinkedIn 上是否在大量招销售、有没有达人白名单计划、博客的产出频率和流量、社区的真实规模。这些都是可以观察到的动作，比任何叙事都可靠。

以 Notion 为例，打完分大致是这样：

| 引擎 | 分数 | 证据 |
|---|---|---|
| 社区与口碑 | 3 | 95% 流量来自有机渠道，r/Notion 超过 34 万成员，TikTok 话题播放量超 10 亿 |
| KOL 达人 | 3 | 头部创作者靠模板和课程月入数万美元，官方几乎不付推广费 |
| 自助式 PLG | 3 | 免费版无限 Block，付费触发点和激活指标都有明确设计 |
| 销售驱动 | 2 | 企业线约占营收 45%，但销售只接 PLG 漏斗溢出的账户 |
| 付费获客 | 0 | 未发现规模化投放 |

这张表比"Notion 是 PLG 典范"这一句话有用得多，因为它告诉你社区和达人才是获客端的主引擎，PLG 负责的是激活和转化。

我自己早期版本的调研也犯过预设答案的错：增长模块的标题直接叫"PLG 增长飞轮"，等于还没查资料就认定了引擎。后来改成中性的"增长引擎"，先打分，再由分数决定写什么。

打完分，一定要加一列"与官方叙事的差异"。最典型的差异就是"PLG 外衣"：产品有自助注册、有免费版，于是被叫作 PLG。但如果获客其实靠达人投放和广告，转化靠促销折扣，那真实的引擎是 KOL 加付费，PLG 只是一层皮。把这种差异写出来，调研才有价值。

## 三、PLG 要单独做一次体检

因为 PLG 是被滥用最严重的标签，只要这个引擎的分数大于等于 1，就要跑一遍成熟度检查。一个闭合的 PLG 循环有五个必要环节和一个加分项：

1. 用户不碰销售就能自助注册
2. 免费版在没有人工介入的情况下能交付真实价值
3. 存在自然发生的 Aha 时刻，不需要别人提示
4. 用户能自助付费升级
5. 没有客户成功团队跟进，用户也能留下来
6. 加分项：使用行为本身会带来传播

然后给出判决：五个环节全通是"闭合"；某几个环节断了是"部分闭合"，要写清断在哪；机制都在但增长实际靠别的引擎推动，是"愿景型"。

拿 Notion 举例，它的 PLG 是闭合的，而且每一环都能找到具体设计。激活阶段用场景模板对抗空白页恐惧，内部不以注册量为 KPI，而是看"至少两名成员一周内访问两次"的激活团队数。付费触发点不在个人侧，而在工作区加入第二个人之后的 1000 个 Block 上限，删除内容还不释放额度，真实团队几天就会撞到。这种拆解才叫调研 PLG，而不是一句"他们是 PLG"。

Aha 时刻和留存机制去哪找？直接搜用户自己写的东西："switched to 产品名"、"how I use 产品名 as a 职业"、论坛里的工作流展示帖、应用商店评价。用户描述"原来可以这样"的那一刻，就是 Aha 时刻的一手证据。

## 四、按分数分配精力，不同引擎看不同的东西

3 分的主引擎花最多篇幅，2 分的次引擎篇幅减半，1 分的提一句就够。每种引擎要回答的问题不一样：

- **PLG**：激活摩擦在哪，Aha 时刻是什么，留存靠什么转换成本，付费的触发时刻，传播是不是使用的自然副产品
- **付费获客**：投在哪些渠道，广告素材用什么钩子，有没有公开的 CAC 信号，是盈利增长还是 VC 补贴
- **KOL**：达人分层和具体名字，是自然提及还是有组织的合作，内容类型，达人带来的是注册还是只有曝光
- **内容与 SEO**：内容类型和产量，核心词还是长尾词，内容到注册的转化路径
- **销售驱动**：目标客户画像，销售流程和周期，合同结构，扩张与续费信号，标杆客户
- **平台捆绑**：母平台怎么分发，用户在平台内怎么发现它，对平台的依赖有多深
- **网络效应**：供需两侧各自的获客和留存，流动性怎么形成，怎么跨过临界点
- **社区与口碑**：用户聚在哪，社区文化为什么有粘性，什么事件会让用户主动推荐

每个问题都要落到具体证据和真实用户原话上。找不到原话就写"未找到一手原话"，绝不把自己的转述包装成引用。

## 五、用公开信号做交叉诊断

单个数据都有噪音，但三个信号放在一起看，能看出增长的质量。三个信号分别是：应用商店的下载与排名、Google Trends 的搜索热度、社交平台的讨论量（国内产品对应微博、小红书、B 站）。

| 下载 | 搜索 | 讨论 | 大概率意味着 |
|---|---|---|---|
| 升 | 升 | 升 | 有机增长或病毒时刻，信号一致 |
| 升 | 平 | 平 | 效果广告在拉下载，没有自然拉力 |
| 升 | 升 | 平 | SEO 或 ASO 驱动，有搜索需求但没人讨论 |
| 平 | 升 | 平 | 有认知没转化，人们搜了但不下载 |
| 平 | 平 | 升 | 只有热闹没有行动，达人噪音或炒作周期 |
| 平 | 升 | 升 | 有兴趣有讨论但没动作，可能有价格或体验门槛 |
| 全平或下降 | | | 增长引擎已经不转了 |

这三个信号都不需要付费工具。Google Trends 直接拉五年曲线，有中文名或别名的产品把两个名字放一起比；应用商店看评分、评论数、下载量区间和分类排名；社交讨论量看官方账号的粉丝和互动，再搜一下有没有千赞以上的爆帖。第三方的下载量监测站大多付费且滞后，拿不到就不要猜。

搜索热度的拐点还要和产品时间线对照：每一个尖峰对应哪次发布、哪次融资、哪次出圈。这样你才知道历史增长是事件驱动还是持续驱动。

## 六、围绕增长的四个配套视角

增长模块不是孤立的，有四个相邻模块会反过来校正你的判断。

**用户画像与切入点。** 把真实用户聚成六到十个画像，估算各自占比，标注哪些被服务得很好、哪些被忽视。Notion 调研里最有价值的结论之一不是功能，而是三类用户的价值排序：企业内部的自发布道者、内容创作者、Z 世代学生。学生短期 LTV 最低，但毕业后会变成第一类人。

**社区与 KOL 网络结构。** 不只是列名单，要区分"入口型"达人和"加深型"达人，找出连接不同圈子的桥梁人物，看受众重叠的集群。这决定了一个新产品该从哪个圈子渗透。

**竞品按引擎选，不按品类选。** 主引擎是 PLG 的，去看相邻品类里同样靠自助增长的产品，它们在抢同一批用户；主引擎是销售的，既要看老牌销售型对手，也要看从下面吃市场的 PLG 新贵。竞品调研最值钱的部分是真实的迁移叙事：谁在从这个产品走向哪里，谁在从哪里走向这个产品，原话是什么。

**时间线与定价。** 发布节奏、明确拒绝做的功能清单、定价阶梯的每一次变化，都是增长策略的物证。

## 七、最后给出判决，并区分可复制与不可复制

调研的终点是五句话的判决：真正驱动增长的是什么，和官方说法差在哪；每个引擎处于哪个成熟阶段；PLG 的体检结论；最脆弱的一环是哪个，它坏了伤害最大；哪些能被新进入者复制，哪些不能。

"最脆弱的一环"这一条也值得多想一步。Notion 的获客端高度依赖创作者生态，如果 AI 让"搭建个人系统"这件事不再需要教程和模板，创作者的变现基础会先于 Notion 的用户量出问题。判断最弱环节，看的就是哪个引擎的前提假设最可能被外部变化推翻。

最后一条最容易被忽略。还是用 Notion 举例：模板和内容生态的 PLG 模型、从产品使用数据识别企业线索的 PQA 流程、大使计划加校园大使的社区基建，这些是方法，可以复制。但 2020 年疫情带来的五倍用户增长是时机窗口，"all-in-one workspace" 的品类心智是先发优势，创始人拿着 200 万美元种子轮做了六年才接受 VC 是极少见的耐心，这些都不可复制。不做这个区分，调研就会变成拜物教。

## 八、贯穿全程的信源纪律

方法再好，信源不严就全白费。几条铁律：

**一手压过二手。** 优先级是创始人个人博客、官网、创始人在论坛的发言、播客长访谈、Hacker News 发布帖，最后才是 Reddit 总结和"十大工具"类文章。

**引用要有原话和链接。** 每一条关于创始人理念或用户痛点的判断，背后都要有原文引用和出处。这不是为了显得严谨，而是因为转述会不知不觉把你的预设塞进别人嘴里。

**挑战前提。** 你手里的背景资料往往有错：创始人数量、融资轮次命名、价格、时间。查到不一致要公开写出修正，不要悄悄改掉，读者需要知道原来哪里错了。

**关键数字分"已验证"和"推断"。** 下载量去应用商店页面看，价格去定价页面看，不要信第三方聚合站，它们普遍滞后。

**不要预填未验证的数字。** 这是最隐蔽的坑。如果你在调研开始时就把"用户一亿、ARR 六亿"写进背景，后面每一个模块都会把它当事实引用，一个错的数字会污染整份报告。所有数字进入上下文前标注"待验证"，最后统一回查五到八个最关键的指标。

**范围纪律。** 调研一个子产品时，母公司的总用户数和融资额不能当作它的数据。找不到就写"单独数据未公开"。

## 结语

如果你调研的目的是为自己的产品找方向，那所有模块最后都要收口到一份决策清单：明确不做什么，在增长、产品、商业三个层面各做哪几个决定，差异化点在哪，从哪个用户群切入。调研不是为了写出一篇好看的报告，是为了让下一个决定少错一次。
